# BILLNOW — MISSING FEATURES & ARCHITECTURAL GAPS
**Project Tagline:** *"Never Forget a Warranty Again."*  
**Audit Date:** November 2026  
**Target:** 100% Production Readiness with ₹0 Monthly Budget

This document details every feature, configuration, and security requirement currently missing from BillNow. Each item is classified by urgency and includes technical requirements for implementation.

---

## 1. Storage & Invoice Management Gaps (Cloudflare R2)

### 1.1 Cloudflare R2 Pre-signed Direct URLs
- **Current State:** The backend streams invoice file binaries directly through FastAPI endpoints (`/api/products/{id}/invoice/view` and `/download`).
- **Missing Capability:** Pre-signed S3 download URLs generated by `boto3` (`generate_presigned_url('get_object', Params={'Bucket': ..., 'Key': ...}, ExpiresIn=...)`).
- **Why It Matters:** Offloads large PDF and image bandwidth directly to Cloudflare R2 (which has **zero egress fees**), preventing the Oracle Cloud VM's CPU and network from bottlenecking.
- **Urgency:** **High (Production Requirement)**

### 1.2 Deep File Signature (Magic Bytes) Sniffing
- **Current State:** Only file extensions (`.pdf`, `.jpg`, `.jpeg`, `.png`) and the client-supplied `Content-Type` header are inspected.
- **Missing Capability:** Validation of file magic numbers (e.g., `%PDF-` for PDFs, `\xFF\xD8\xFF` for JPEGs, `\x89PNG\r\n\x1A\n` for PNGs) to prevent polyglot attacks and malicious executable uploads disguised as invoices.
- **Urgency:** **High (Security Requirement)**

## 2. Notification & Background Automation Gaps

### 2.1 Automated Background Scheduler (Daily Warranty Scans)
- **Current State:** `generate_warranty_notifications()` exists as an internal function called during tests or when users manually open the app.
- **Missing Capability:** An automated background runner (APScheduler in FastAPI lifespan or a dedicated systemd service / cron job) that wakes up daily at 00:00 UTC, iterates all active users, evaluates warranties, and generates notifications.
- **Urgency:** **Critical (Core Value Proposition)**

### 2.2 Firebase Cloud Messaging (FCM) Push Notifications
- **Current State:** `NotificationPreference.push_enabled` exists as a database boolean, but no device token storage or push dispatch logic exists.
- **Missing Capabilities:**
  1. `DeviceToken` database model (`user_id`, `token`, `platform`, `created_at`, `last_used_at`).
  2. API endpoints: `POST /api/notifications/fcm-token` (register device token) and `DELETE /api/notifications/fcm-token` (unregister device token on logout).
  3. FCM HTTP v1 API client using Firebase Admin SDK to dispatch native push notifications when warranties reach milestone days (30, 7, 1).
- **Urgency:** **High (Mobile Experience)**

---

## 3. Email Integration Gaps (Brevo Free Tier)

### 3.1 Brevo SMTP / API Integration & Sender Verification
- **Current State:** `backend/app/services/email.py` uses generic Python `smtplib`. In development, emails are logged to the console unless an external SMTP is configured.
- **Missing Capabilities:**
  1. Production configuration for Brevo SMTP relay (`smtp-relay.brevo.com:587`) or Brevo Transactional Email REST API v3.
  2. Verified Sender configuration instructions (SPF, DKIM, DMARC DNS records).
  3. Graceful handling of Brevo's 300 free emails/day threshold to prevent crashes if the quota is reached.
- **Urgency:** **Medium (Essential for Production Auth & Alerts)**

---

## 4. Compliance & Account Management Gaps

### 4.1 Standalone Public Legal Pages (`/privacy` and `/terms`)
- **Current State:** Brief two-paragraph summaries exist inside a popup modal on `SettingsPage.tsx`. There are no standalone public URLs.
- **Missing Capabilities:**
  1. Dedicated public web pages `/privacy` and `/terms` in the frontend router.
  2. Full GDPR / Google Play compliant text covering data collection, Neon DB storage, Cloudflare R2 invoice storage, cookie policy, and user rights.
  3. Footer links on landing page, splash page, login, and registration pages.
- **Urgency:** **Critical (Mandatory for Google Play Store Publication)**

### 4.2 Standalone Verified Account Deletion Flow
- **Current State:** Account deletion is only possible through authenticated `DELETE /api/settings/account`.
- **Missing Capabilities:**
  1. Google Play Store requires developers to provide a public web page where users can request account and data deletion without needing to reinstall the app.
  2. Public endpoint: `POST /api/auth/request-account-deletion` (sends confirmation email with secure token).
  3. Public web page `/delete-account` allowing users to confirm deletion via token.
  4. Require password confirmation on authenticated account deletion within the mobile app.
- **Urgency:** **Critical (Mandatory for Google Play Store Publication)**

### 4.3 Data Export in CSV Format
- **Current State:** `GET /api/settings/export` generates a JSON dump.
- **Missing Capability:** `GET /api/settings/export?format=csv` returning a zipped or formatted CSV file containing products, purchase details, warranty dates, and maintenance logs for easy import into Excel or Google Sheets.
- **Urgency:** **Medium**

## 5. Mobile & Android Gaps (Capacitor Native Integration)

### 5.1 Capacitor Configuration & Android Project Setup
- **Current State:** The frontend is a responsive web application styled for mobile viewports, but has no native mobile bridge.
- **Missing Capabilities:**
  1. Install `@capacitor/core`, `@capacitor/cli`, and `@capacitor/android`.
  2. Generate `capacitor.config.ts` with App ID `com.billnow.app`, App Name `BillNow`, and `webDir: "dist"`.
  3. Initialize native Android project folder (`/android`) with Gradle build scripts.
  4. Configure Android manifest permissions: `INTERNET`, `POST_NOTIFICATIONS`, `READ_MEDIA_IMAGES`.
  5. Generate adaptive Android app icons and native splash screens.
- **Urgency:** **High (Required for Native APK/AAB Builds)**

## 6. Backend Hardening & Database Optimization Gaps

### 6.1 Database Connection Pooling Tuning
- **Current State:** `backend/app/db/session.py` initializes SQLAlchemy `create_engine` with only `pool_pre_ping=True`.
- **Missing Capabilities:**
  1. Production connection pool configuration: `pool_size=10`, `max_overflow=20`, `pool_recycle=1800`, `pool_timeout=30`.
  2. Neon pooler connection validation (`sslmode=require&channel_binding=require`).
  3. Automated database backup script (`pg_dump` to encrypted Cloudflare R2 bucket) and restore documentation.
- **Urgency:** **High (Stability & Reliability)**

### 6.2 Health Check with Live Database Connectivity Probe
- **Current State:** `GET /api/health` returns static JSON (`{"status": "ok"}`).
- **Missing Capability:** Execute a lightweight database probe (`SELECT 1`) within the health check endpoint to accurately report database connectivity to monitoring services (e.g. UptimeRobot) and load balancers.
- **Urgency:** **Medium**

### 6.3 OTP Brute-Force & Memory Store Protection
- **Current State:** `_otp_cache` is stored in an in-memory dictionary.
- **Missing Capabilities:**
  1. Per-email attempt counters (block after 3 failed OTP entries to prevent brute-forcing).
  2. Automatic expiration pruning to prevent memory growth over extended uptime.
- **Urgency:** **High (Security Requirement)**

## 7. Deployment & Infrastructure Automation Gaps

### 7.1 Oracle Cloud Always Free VM Automation Scripts
- **Current State:** No automated server provisioning or deployment scripts exist in the repository.
- **Missing Capabilities:**
  1. `setup_server.sh`: Installs Python 3.12, Nginx, Uvicorn, Certbot, Fail2ban, and firewall rules (`ufw`) on Ubuntu ARM64.
  2. `deploy_backend.sh`: Pulls latest code, activates virtualenv, runs `alembic upgrade head`, and restarts systemd service.
  3. `billnow.service`: Systemd service unit file managing Uvicorn workers.
  4. `billnow_scheduler.service` & `timer`: Systemd units managing daily warranty reminder runs.
  5. `nginx.conf`: Nginx configuration with TLS 1.3, rate limiting, gzip/brotli compression, and reverse proxy to Uvicorn.
- **Urgency:** **Critical (Deployment Prerequisite)**

### 7.2 Cloudflare Pages Configuration
- **Current State:** Static build outputs to `frontend/dist/`.
- **Missing Capabilities:**
  1. Cloudflare Pages build settings specification (Build command: `npm run build`, Output directory: `dist`).
  2. Client-side routing rewrite rule (`_redirects` file with `/*  /index.html  200`).
- **Urgency:** **High (Frontend Hosting Prerequisite)**
